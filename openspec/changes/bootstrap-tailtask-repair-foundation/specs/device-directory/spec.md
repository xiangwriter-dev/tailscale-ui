# Spec Delta

## Purpose

为用户提供可信的 Tailscale 设备目录，支持识别设备、选择目标、保存本地偏好和继续添加设备。目录明确区分网络观测、历史记录和应用修复授权，避免缓存、同名设备或账户切换造成误认。

## ADDED Requirements

### Requirement: 展示可识别的设备目录

客户端 SHALL 展示当前网络上下文中可观测的本机及对端设备；每项包含稳定节点标识、名称、系统、可用地址、网络状态及观测时间。系统 MUST 使用节点标识区分设备，不以名称或地址代替身份。

#### Scenario: 同名设备选择

- **WHEN** 当前网络存在两个名称相同、节点标识不同的设备
- **THEN** 目录保留两个独立项目，选择后详情对应所选节点，别名和收藏互不覆盖。

#### Scenario: 缺少在线字段

- **WHEN** 某节点没有有效的在线状态
- **THEN** 该节点显示“状态未知”，不能被归类为已确认在线或已确认离线。

### Requirement: 网络上下文与历史状态隔离

客户端 SHALL 将设备偏好和历史观测绑定到网络上下文；上下文变化时清除当前选择。只有已确认当前上下文时才允许在该上下文内展示历史设备；历史条目 MUST 标记“历史观测”及观测时间，不能表现为实时在线或已授权。

#### Scenario: 切换账户或网络

- **WHEN** 新一次有效观测的上下文与上一次不同
- **THEN** 客户端清除原选择，只展示新上下文目录，不把旧上下文的别名、收藏或设备条目混入其中。

#### Scenario: 当前身份无法确定

- **WHEN** 应用启动后尚未获得有效上下文，或当前状态要求重新登录
- **THEN** 实时设备列表为空并解释原因，不自动载入上次账户目录充当当前目录。

#### Scenario: 观测失败或节点消失

- **WHEN** 已识别上下文中的刷新失败，或本次成功刷新中不再包含原节点
- **THEN** 保留的旧条目明确标记历史观测，不进入“网络在线”结果，旧选择不能被描述为当前有效连接。

### Requirement: 搜索和本地偏好持久化

客户端 SHALL 支持按名称、别名和地址搜索，支持全部、在线、离线或未知、收藏筛选，并将别名与收藏保存到本地存储；修改本地别名 MUST NOT 修改远端主机名称或 Tailscale 配置。

#### Scenario: 偏好在重启后保留

- **WHEN** 用户给节点设置中文别名并收藏，关闭后在同一上下文重新打开应用
- **THEN** 该节点保留别名和收藏，搜索别名可找到节点，源名称仍可在详情查看。

### Requirement: 可理解的网络故障

客户端 SHALL 区分未安装 Tailscale、需要登录、服务停止或不可用、权限不足、格式未知及正常就绪，并提供对应的恢复提示；失败不能被当成有效的“零设备在线”。一次读取 MUST 在 10 秒内结束等待并给出结果或错误。

#### Scenario: 读取权限不足

- **WHEN** 官方客户端存在但系统拒绝读取状态
- **THEN** 显示“权限不足”及检查本机 Tailscale 运行权限的提示，不静默提权、不显示所有设备离线。

#### Scenario: 状态格式发生变化

- **WHEN** 返回内容不合法，或缺少识别当前网络所必需的信息
- **THEN** 显示“无法识别状态”，保留错误诊断但不推测设备身份或在线状态。

### Requirement: 新增设备引导与权限分离

客户端 SHALL 提供随时可再次进入的新增设备引导，说明在新设备安装官方 Tailscale、加入预期网络、按需要完成管理员审批及重新发现。客户端 MUST 分别表达“网络在线”和“修复授权”；此基础版本不建立远程修复连接。

#### Scenario: 新设备加入后发现

- **WHEN** 用户在另一设备完成官方 Tailscale 加入流程且该设备对本机可见，随后选择重新发现
- **THEN** 新设备出现在列表且可选择；详情的远程修复状态仍为“未配对 / 尚未开放”，不会因网络在线而自动取得权限。

#### Scenario: 新设备尚不可见

- **WHEN** 引导完成后本机仍无法观测新设备
- **THEN** 提示检查目标登录、管理员审批及网络策略，不捏造节点，也不自动修改 Tailnet 策略。
