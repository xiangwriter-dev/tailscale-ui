# Spec Delta

## Purpose

提供适合日常查看设备与修复记录的跨平台桌面界面，落实用户指定的简约风格和适量科技元素。利用 GPT Image 概念图指导视觉实现，同时保证实际界面可操作、状态可信、文本清晰且支持基本无障碍使用。

## ADDED Requirements

### Requirement: 简约科技视觉和生图设计依据

界面 SHALL 采用克制的层次、留白、细边框、清晰文字及少量网络科技元素；设计过程 MUST 使用 GPT Image 生成概念图并保存所选图片、最终提示词及其示例性质说明。实际控件与文字不得用整张截图代替。

#### Scenario: 设计成果可追溯

- **WHEN** 开发者查看项目设计资料
- **THEN** 能找到所选 GPT Image 概念图及提示词，并识别其中设备、日期和版本均为示例；运行客户端显示真实控件和真实数据。

### Requirement: 四个主要工作页面

客户端 SHALL 提供设备、任务记录、本机修复、设置四个明确入口。设备页提供新增设备入口和选中详情；任务页提供分页记录、阶段与结果详情；设置显示版本、数据位置及可保存的刷新间隔。

#### Scenario: 从列表查看选中设备

- **WHEN** 用户选择设备并进入详情
- **THEN** 详情对应所选节点，展示可用地址、系统、网络观测及修复授权状态，缺失信息显示未知或不展示，不填入概念图示例。

#### Scenario: 查看修复进展

- **WHEN** 用户发起本机修复后查看任务页
- **THEN** 能找到该任务及真实状态，在结果未知时显示当前阶段或不定进度提示，不用假百分比表示完成程度。

### Requirement: 加载与异常状态完整表达

客户端 SHALL 为加载、无设备、无匹配结果、网络故障、历史缓存、任务失败和权限未开放提供不同说明。应用运行在无桌面桥接的浏览器环境时 MUST 明确标识仅为预览，不能以示例数据伪装真实设备或已执行任务。

#### Scenario: 浏览器预览

- **WHEN** 页面在没有桌面运行时能力的普通浏览器中打开
- **THEN** 显示预览说明，真实设备读取及执行操作不可用；演示数据若用于独立设计预览，必须明显标记且不进入应用持久数据。

#### Scenario: 网络读取失败

- **WHEN** 用户刷新设备失败
- **THEN** 页面显示明确错误与重试入口，保留可理解的页面布局，不通过成功提示掩盖失败。

### Requirement: 可访问性与桌面尺寸适配

界面 SHALL 支持 1024×720 及更大窗口、键盘导航、可见焦点、中文长名称截断并可查看全文。状态 MUST 同时有文字，不能仅依赖颜色；正文与背景对比度至少 4.5:1，操作目标至少 32×32 CSS 像素。减少动态效果偏好 SHALL 得到尊重。

#### Scenario: 小窗口键盘操作

- **WHEN** 用户在 1024×720 窗口通过键盘选择设备、打开任务详情、关闭对话框
- **THEN** 操作均可到达且焦点清晰，主操作没有被遮挡，关闭后焦点返回合理位置。

#### Scenario: 减少动画

- **WHEN** 系统启用减少动态效果
- **THEN** 装饰性动画关闭；活动任务仍通过文字显示当前阶段，状态含义不丢失。

### Requirement: 本地偏好保存与错误反馈

客户端 SHALL 保存用户选择的设备刷新间隔，并在下次启动恢复。保存失败 MUST 给出错误且不声称成功；页面隐藏时无需持续刷新设备。

#### Scenario: 设置保存失败

- **WHEN** 用户改变刷新间隔但后端未成功保存
- **THEN** 保留或恢复原有效设置，显示保存失败，不显示“已保存”。
