# Spec Delta

## Purpose

使用户能够从明确归属的 GitHub 仓库取得可复现源码与适合其平台的安装产物，并知道每个平台实际验证和签名的状态。交付必须覆盖安装、启动与数据保留验证，不能把构建脚本存在等同于可用产品已发布。

## ADDED Requirements

### Requirement: 三平台安装产物

发布流程 SHALL 为 Windows x64 提供 NSIS `-setup.exe` 安装器、为 macOS arm64 与 x64 提供 DMG、为 Linux x64 提供 AppImage 与 deb，并标明支持的操作系统版本和架构。构建失败的平台 MUST 标记未交付。

#### Scenario: Windows 用户下载安装

- **WHEN** Windows 用户下载对应架构的发布安装器并完成安装
- **THEN** 获得可启动的 TailTask 桌面程序及卸载入口；交付文件为安装器而非重命名的裸可执行文件。

#### Scenario: 平台构建尚未完成

- **WHEN** macOS 或 Linux 构建失败或尚未运行
- **THEN** 发布记录写明该平台未交付，不声称“三平台已完成”。

### Requirement: 安装、升级与数据保留

客户端 SHALL 把应用数据放在当前用户的应用数据位置，安装和常规升级不得删除既有任务及偏好。更新失败 MUST 保留原数据并报告原因；迁移失败不得静默重建空数据库。

#### Scenario: 覆盖安装或升级

- **WHEN** 用户已有任务和设备偏好，安装相同版本或兼容的新版本
- **THEN** 应用启动后仍可查看原任务和偏好，版本信息与安装产物一致。

#### Scenario: 数据版本不兼容

- **WHEN** 较旧应用遇到无法兼容的较新数据库
- **THEN** 停止不安全的数据写入并说明版本不兼容，原数据文件保留。

### Requirement: 源码仓库与发布资产

项目 SHALL 在用户授权且完成身份验证的 GitHub 账户下创建新的 `tailscale-ui` 公开仓库，并上传审核后的源码、锁文件、规范和构建说明。凭证、用户数据库、真实设备快照、日志、缓存与本地工具链 MUST 排除。版本资产 SHALL 包含版本、架构、校验摘要和变更说明。

#### Scenario: 尚无有效 GitHub 登录

- **WHEN** 无法取得有效登录账户或仓库写入权限
- **THEN** 报告准确阻塞原因及本地成果位置，不将电子邮箱猜测为用户名，不声称仓库已经创建或源码已上传。

#### Scenario: 发布文件检查

- **WHEN** 准备上传源码和安装包
- **THEN** 上传清单只包含项目源码与必要交付文件，安装包有对应 SHA-256 校验摘要，真实用户数据和生成缓存不在清单内。

### Requirement: 构建验证与签名状态透明

交付记录 SHALL 分开记录类型检查、单元测试、各平台打包、安装运行验证和签名/公证状态。正式发布 MUST 具有相应平台的实际验证记录；无签名材料时只能提供明确标注的测试构建，不能宣称已签名或无系统提示。

#### Scenario: 测试构建缺少签名材料

- **WHEN** Windows 或 macOS 安装包没有正式签名或所需公证
- **THEN** 发布说明明确标为测试构建并记录签名状态，不伪造已验证发布者或公证结果。

#### Scenario: 锁定依赖后构建

- **WHEN** 在干净的对应平台构建环境按文档安装锁定依赖并运行检查
- **THEN** 可完成对应构建步骤，日志能定位失败环节；任何失败检查不会被“已有源代码”或其他平台的成功代替。
