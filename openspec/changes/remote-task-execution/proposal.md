# Proposal

## Why

用户已撤回“Agent 只有修复、没有操控权”限制，恢复原始远程任务需求。xiangwriter远程器 需要支持选择设备、配对执行端、主动提交命令/脚本并查看真实进度和结果，补齐 0.1.0 基础版尚未提供的能力。

## What Changes

- 增加同一桌面安装中的本机执行端，由设备所有者开启；执行进程与 UI 生命周期独立。
- 增加仅绑定 Tailscale 地址的 TLS 服务、证书指纹配对、短期一次性配对凭据和可撤销控制端令牌。
- 允许用户明确提交 exec 与 script 任务，使用目标账户权限和允许工作目录；不做透明提权。
- 增加持久队列、幂等提交、分页日志、进度、退出结果、取消/超时和中断恢复。
- 增加受限结果文件收集与校验下载、本地远程历史和断线重连。
- 设备详情新增配对/运行入口，新增本机执行端页面，原数据库维护保留独立入口。
- 三平台安装包更新为 xiangwriter远程器；构建、安装实测和功能验收分别报告。

## Capabilities

### New Capabilities

- `remote-agent-access`：执行端开启/关闭、TLS 身份、配对、凭证保护与撤销。
- `remote-task-execution`：远程命令与脚本、队列、日志、取消、幂等、恢复与结果文件。
- `remote-desktop-workflow`：设备配对/任务提交界面、本机执行端设置、本地历史与安装集成。

### Modified Capabilities

无已归档主规格；原基础变更仍单独跟踪未完成的平台验收。其“仅修复”边界不再作为后续产品限制。

## Impact

影响 Rust 核心与 Agent、Tauri IPC/生命周期、React 任务页面、SQLite 模式、凭证存储、平台进程管理以及 CI 打包。新增服务默认关闭；不自动在其他机器部署或执行任务。测试只运行明确的合成命令和独立目录，不能以测试名义运行用户未请求的远程副作用。
