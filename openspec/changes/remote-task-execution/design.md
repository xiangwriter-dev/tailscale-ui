# Design

## Context

现有 0.1.0 工程有真实 Tauri IPC、Tailscale 设备目录、本机 SQLite 与修复任务；数据库模式 2、按目录独占锁、迁移前备份已通过测试。原远程任务 PRD 是需求来源；用户撤回修复限制后，需要增加可配对的执行端，不能通过修改按钮文案假装已有远程能力。

## Goals / Non-Goals

Goals：保持单一安装体验；控制端和执行端使用独立数据库及独立进程；先持久接受后运行；任务所有权、身份与结果明确；三平台对应原生进程管理。

Non-Goals：屏幕串流、模拟鼠标键盘、透明管理员提权、自动部署到用户尚未指定的其他机器。允许工作目录不是恶意脚本沙箱，执行权限等同用户账户。

## Decisions

1. 同一桌面可执行程序增加明确的后台 Agent 启动模式；UI 通过受认证的本地管理连接控制 Agent。避免要求用户手动安装第二套软件；不让窗口生命周期决定任务生命周期。无桌面 Linux 保留 CLI serve 入口。
2. 执行端使用 Rust HTTP/TLS 服务，绑定已验证 Tailscale 地址，默认端口 47321。原始网络请求使用固定协议和大小/超时限制；禁用环境代理和重定向。使用本地生成证书，配对信息传递完整证书与 SHA-256 指纹；客户端只信任该证书并验证地址。
3. 配对会话、授权和令牌摘要写入 Agent SQLite，配对有效期 5 分钟和错误次数上限 5。成功换取 256 位随机令牌，令牌只经 TLS 返回。客户端通过平台 keyring 存储凭证，SQLite 保存引用。凭证存储不可用时报告错误，不能降级为明文 SQLite。
4. SQLite 新增角色分离的远程连接、提交观察、Agent 任务/事件/授权/结果表；保留既有本机修复表和不可变迁移。Agent 与控制端目录独立，各自独占。请求摘要覆盖命令、参数、目录、环境、模式、超时、结果配置。事务持久接受后才通知队列。
5. 队列默认并发 1，最大 4。启动前持久化 starting 和运行实例 ID；执行进程与数据库之间不可原子提交，故不承诺外部副作用恰好一次。重启后未知状态进入 recovery_required，不依靠复用 PID 杀任意进程。
6. exec 按参数数组启动，script 写入任务私有临时脚本并使用真实解释器。Windows 使用 Job Object 管理子进程：受控 worker 先加入 Job 再释放启动屏障，避免用户进程在加入 Job 前派生子进程；POSIX 使用独立进程组。只操作已持有的执行实例，不按不可信 PID 字符串杀进程。
7. 输出通过有界通道和事件批次写入，保留单调序号；分页轮询先满足恢复与实时查看，后续 SSE 可优化。限制单任务输出，超限记录截断事件并继续排空管道。取消/超时完成进程收束后写终态，存储失败必须显示待核实。
8. 结果只从规范化的允许工作目录下收集普通文件，拒绝 symlink、目录穿越与特殊文件；复制到 Agent 专用结果区并固定 manifest；任务归属验证后按 artifact ID、Range 下载，客户端 .partial 写入、摘要校验后改名。
9. UI 分开本机维护和远程执行。增加设备配对/任务表单、本机执行端页面、远程日志/参数/结果；控制端提交请求先落库，保存未知提交便于重试，禁止详情读取失败重新生成请求。
10. Windows 当前用户安装，macOS 分架构 DMG，Ubuntu 24.04 AppImage/deb。登录后自启适配分别使用 Windows 用户登录任务、LaunchAgent、systemd 用户单元；注册失败不得误报。CI 验证构建，真实网络和原生窗口验收另记录。

## Risks / Trade-offs

- 执行任意命令具有当前用户权限 → 目标所有者显式开启并配对、令牌隔离和撤销、每次任务主动提交；不承诺目录沙箱。
- 令牌交付响应可能丢失 → 失败配对在所有者处撤销重建，客户端持久保存成功接收的凭证后才显示已配对。
- 地址或身份变化 → 每次提交校验当前节点，证书/Agent 身份不匹配时要求重新配对。
- Agent 故障与外部进程存活 → 平台进程容器尽力收束，不确定结果保持待核实，不自动重跑。
- 缺少 macOS/Linux 实机与签名 → CI 只证明检查/打包；对应实机验收、签名状态如实记录，不能伪称通过。

## Migration Plan

追加模式 3，升级前备份；旧模式 2 基础版降级时拒绝打开较新库。安装默认不开启服务；新 UI 的功能必须随真实能力完成才显示可用。保留 0.1.0 基础测试产物，远程版本使用后续版本号，分别记录功能与验证。
